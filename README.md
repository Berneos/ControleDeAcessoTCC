# 🛂 Controle de Acesso

**Controle de Acesso** é um sistema versátil desenvolvido para permitir
que **múltiplas empresas utilizem a mesma aplicação simultaneamente**,
diferente de soluções tradicionais que atendem apenas uma organização
por vez.

O projeto foi desenvolvido como **Trabalho de Conclusão de Curso (TCC)**
do 3° ano do Ensino Médio Técnico em Informática. Ele surgiu como
expansão de um aplicativo criado no 2° ano, evoluindo para uma solução
completa com back-end robusto, front-end multiplataforma e integração
com hardware (Arduino).

------------------------------------------------------------------------

## 🚀 Tecnologias Utilizadas

### **Back-end**

-   **Java 17**
-   **Spring Boot**
-   **PostgreSQL**
-   **Railway (Deployment)**
-   **API REST** para comunicação com o front-end

### **Front-end**

-   **HTML**
-   **CSS**
-   **JavaScript**

### **Hardware**

-   **Arduino** --- usado como protótipo de catraca física

## 🧠 Funcionalidades

### 🔐 **Autenticação e Perfis de Acesso**

-   Usuário Comum\
-   Usuário Administrador\
-   Usuário Master (desenvolvedores)

### 👤 **Gerenciamento Completo**

-   Cadastro e edição de **usuários**
-   Cadastro e gerenciamento de **pessoas**
-   Registro de **catracas físicas**
-   Monitoramento e **gerenciamento geral do sistema**

### 🔄 **API REST**

Sistema totalmente estruturado em API REST para isolamento entre
front-end e back-end.

### 🔌 **Integração com Arduino**

Protótipo funcional de catraca física para testes e demonstrações.

------------------------------------------------------------------------

## ▶️ Como Rodar o Projeto

### **1. Back-end**

O back-end está hospedado na Railway, porém **fica desligado para evitar
custos**.

Para testar:\
Entre em contato para ativação do servidor.

-   Back-end: controledeacessotcc-production.up.railway.app\
-   Swagger:
    controledeacessotcc-production.up.railway.app/swagger-ui/index.html#/

### **2. Front-end**

Como o sistema completo não está hospedado:

1.  Baixe o repositório
2.  Abra `index.html` no navegador
3.  Certifique-se de que o back-end esteja online
